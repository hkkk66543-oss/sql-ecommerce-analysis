## 本次修改

补齐 `01` 的 9 张 ODS 表和 `03` 的 4 张经营 ADS 表；新增只读校验 `06` 和原始 CSV 日期转换工具。另在 `02` 开头补上其引用但从未创建的 `dwd_order_review_summary`，避免空库首次执行报表不存在。未修改 Power BI、图片或 ADS 样例文件。

使用 MySQL 8.0，金额为 DECIMAL，订单主键为 order_id，商品明细主键为 (order_id, order_item_id)，支付主键为 (order_id, payment_sequential)。评价 ID 和邮编可能重复，不能强行作为主键。ODS 不添加外键，以便自由安排导入顺序；通过 `06` 检查孤儿记录。`CREATE TABLE IF NOT EXISTS` 不迁移已有表结构，已有数据库需要先检查 `SHOW CREATE TABLE`。

## 执行顺序

请使用独立的测试 MySQL 实例或空数据库。历史 `02/04/05` 有 DROP TABLE，不能直接在生产分析库重跑。本次 `01` 不清空原始表，`03` 不删除或替换已有 ADS 表；如表已存在，停止执行并先自行归档或换空数据库。客户端必须配置遇错停止，mysql CLI 不要使用 `--force`。

1. 下载 README 指向的 Kaggle Olist 原始数据。
2. 执行 `01_create_database_and_tables.sql`。
3. 执行 `python scripts/prepare_olist_csv.py /path/to/raw /path/to/new_prepared`。输出目录必须不存在；工具不修改输入文件。不识别的日期会报错，出错后的不完整输出目录不要用于导入。
4. 用 Navicat 的 CSV 导入向导导入转换后的文件，按以下映射导入已有表，使用字段名映射，不创建 `olist_*` 新表。编码 UTF-8，首行为标题，分隔符逗号，双引号限定字段；保留评价中的换行和逗号。空日期及空数值设为 SQL NULL，不用零或空字符串代替数值。检查导入日志，不使用 IGNORE/REPLACE 隐藏重复键。邮编按字符导入以保留前导零。
5. 执行 `02`，再执行 `03`，之后执行 `06`。若需要重建其他 ADS，再按原流程执行 `04/05`，但该部分不属于本次完整数据实跑验证。
6. 逐条检查 `06` 的结果与样例；必要时在测试库导出新的 CSV 进行逐月、逐状态、逐支付方式比对，不覆盖仓库现有样例。

## 日期及评价兼容性

已有 `02/04/05` 使用 `%c/%e/%Y %H:%i` 解析文本日期。因此 ODS 时间字段使用 VARCHAR，转换工具将 ISO 日期转换成该格式，空值保留为空供导入时转换为 NULL。秒截断到分钟，与历史脚本精度一致；它会损失秒精度，分钟边界附近的物流时长可能受影响。源 CSV 保留供审计。`03` 额外支持带秒 ISO 下单时间，但不能因此跳过完整流程的日期转换步骤。

缺失的评价汇总采用每订单平均评分、最新评价创建/答复时间及原始评价行数，确保关联时一行订单只匹配一行评价。最大日期先解析再聚合，不能按月/日/年文本直接排序。历史评价选择策略无法从 ADS 汇总反推；该策略是明确的补全选择，不能宣称已复现历史物流评分或 RFM 分群结果。原始重复评价行由导入质量检查处理，不任意删除。

## 指标口径与防重复

| 输出 | 来源与粒度 | 口径 |
| --- | --- | --- |
| ads_business_overview | delivered 商品明细先聚合至订单 | 商品 GMV 不含运费；订单数为有商品明细的已交付订单；AOV=GMV/订单数；运费占比=运费/GMV |
| ads_monthly_business_trend_stable | 同上，按下单月份 | 2017-01-01（含）至 2018-09-01（不含），与现有 20 个月样例范围一致 |
| ads_order_status_analysis | 原始 orders，一行一订单 | 包括全部状态及没有商品明细的订单；占比基于全部订单 |
| ads_payment_type_analysis | 原始 order_payments，一行一笔支付 | payment_count 为支付记录数，order_count 为该方式去重订单数；金额及平均值按支付记录计算，包含全部状态 |

delivered 范围与现有 DWD 用户购买口径及样例 delivered=96,478 一致，但文档未完整写明历史筛选条件，因此需要原始数据实跑确认。总览不要求签收日期非空，不施加物流清洗条件。月度范围是从样例确定的展示范围，不是全历史边界。

`03` 用临时表的 (order_id, order_item_id) 主键拒绝重复 DWD 行。COUNT(DISTINCT order_id) 只能解决订单计数，不能修复重复金额；也不能用 SUM(DISTINCT price)，因为不同商品可以价格相同。经营汇总不关联支付明细或评价明细，防止多对多膨胀。订单日期解析失败会计入总览但无法进入月度，必须检查 `06` 的日期覆盖结果。分母为零时指标返回 NULL，表示没有可定义的比率。

支付金额包含运费且包含其他订单状态，不能拿来直接核对商品 GMV。同一订单可使用多个支付方式，各方式的去重订单数不能相加当作平台订单数。
